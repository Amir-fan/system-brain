# ADR

Architectural Decision Records are reserved for important architecture decisions only.

Use ADRs when a decision changes boundaries, ownership, dependency direction, persistence strategy, or another platform-level rule that should be traceable over time.

## File naming
Future ADR files must use:
- ADR-001-short-decision-name.md
- ADR-002-short-decision-name.md

## Required sections
Each ADR should include:
- Status
- Date
- Context
- Decision
- Alternatives
- Consequences

Do not create ADRs just to fill the folder.
